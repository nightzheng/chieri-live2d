# 1.3.1 覆盖安装目录修复

1.3.0 的安装检查只把注册表登记的路径当作旧目录。登记缺失时，旧程序目录会触发非空目录拦截。安装向导也可能给自定义名称的旧目录再加一层应用子目录。

1.3.1 优先保留登记的安装路径，也通过 `千绘莉.exe`、`resources\app.asar` 和 `resources.pak` 识别无安装登记的旧位置。识别后可以覆盖该目录。无关的非空目标仍受保护。旧安装没有登记时，安装器覆盖本次发行的文件，保留未覆盖的文件。在线版即使遇到旧版留下的本地模型文件，也按在线版运行。

选旧目录时，输入直接包含 `千绘莉.exe` 的路径，例如 `D:\桌宠\雪村千绘莉\nekomimi-pet`。应用身份、配置和记忆数据库位置沿用 1.3.0。

自动化回归可使用 PowerShell 7 运行 `./tests/installer-location-smoke.ps1`。脚本用随机安装标识、独立测试目录及禁用快捷方式的在线版执行 NSIS，保留真实安装的登记与文件。实际安装向导的手动点击和正式安装身份下的用户环境覆盖安装 **Not Run**。

Windows 实测通过了三个场景。

1. 拒绝只有无关文件的非空目标，原文件完好。
2. 覆盖未登记的自定义名称旧目录，替换程序文件、保留额外文件并登记原路径。
3. 已登记的自定义目录以末尾带反斜杠的路径重装，仍使用原路径，目录外的测试数据保留。

27 项项目自动化测试通过。在线版和完整版均已重新构建。
